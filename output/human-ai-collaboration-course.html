模块 01 / 认知重构

协同的本质是什么

人机协同的本质，不是静态地划"AI干什么、人干什么"，而是动态地把人的判断力，从脑子里传递到AI可执行的流程里。

四层递进分工模型

分工不是一张静态表，是四层递进结构。越往上越核心，越往下越容易外包。

04 进化分工 谁在变好？
人 · 往上游走
把隐性判断显式化（判断档案）。不断把低层任务交出去，自己往更高层走。
AI · 往下游接
按显式化的判断执行。随着判断框架越来越清晰，承担越来越多的任务。
传递过程：第一次做→人全程参与+提取判断样本；第二次→人给框架AI执行；第三次→AI自主执行人只验收异常；第N次→完全由AI承担。
03 知识分工 谁记住什么？
人记住
"意味着什么"——判断、风格、直觉、为什么这么定、下次遇到类似的怎么判断。
AI记住
"发生了什么"——事实、过程、上下文。什么文件在哪、上次怎么定的、谁说了什么。
02 判断分工 谁定标准？
人只握两个环节
判断决策（做出裁决）+ 结果验收（确认对不对）。这两个环节不可外包。
AI承接四个环节
信息收集 → 信息整理 → 模式识别 → 执行落地。判断前后的"体力活"都可以外包。
陷阱：AI整理得不对，人的判断就建立在错误信息上。不能把AI当裁判。
01 执行分工 谁做？
人做
低频高价 + 不可逆 + 创造性跳跃。关键决策、危机处理、从0到1的框架。
AI做
高频重复 + 可验证 + 模式匹配。编程、格式转换、数据汇总、分类检索。
实证：40万次Claude Code真实对话——人做约70%规划决策（What），AI做约80%执行决策（How）。

模块 02 / 日常协同

给AI写操作手册

README.md是给人看的项目门面，AGENTS.md是给AI看的项目操作手册。通过机器友好的Markdown格式，以极低Token成本让AI"瞬间入职"。适用于日常单次任务——你给AI规则，它按规则执行，你验收结果。

AGENTS.md 五条最佳实践
01
用强语气词
用 Must / Never / Always，效果远好于 Should / Recommend。AI对强指令的遵从度显著更高。
02
提供正误对比
展示 错误 vs 正确，是最高效的沟通方式。比写500字描述规则，不如给一对正反示例。
03
机器友好格式
多用表格、列表、代码块。AI处理结构化数据远优于散文。把命令、路径、参数用表格呈现。
04
单一职责
只写工程规范，不写业务逻辑。业务逻辑让AI通过阅读代码/文档获取。文件不超过200行。
05
禁令清单最重要
明确写出 Don'ts。必须包含安全约束（如"禁止将API Key写在代码里"）。这是防止AI"好心办坏事"的关键。
!
防坑
最常见错误：①含糊其辞（"写高质量代码"是废话）②信息过时 ③文件太大 ④忘记安全约束
练习卡 给一个高频重复工作写AGENTS.md
动作

方法
AGENTS.md 五条最佳实践
验收
AI读完文件后能独立完成该任务，你只需审批结果
误区
把业务逻辑写进去（应只写工程规范）；文件超过200行
时间
约2小时
模块 03 / 项目协同

用项目管理思维控场

把使用AI从"写代码做任务"升级为"AI辅助项目管理"。适用于有明确开始和结束的标准项目——1-4周。

PMP 五阶段时间线
① 启动 · 定调
要做什么？不做什么？验收标准？
→ PROJ.md
② 规划 · 拆解
不写代码，先拆任务，列风险和验证方式
→ PLAN.md
③ 执行 · 小步快跑
按计划执行，逐步交付
→ 代码/文档
④ 监控 · 门禁检查
边做边检查，防止偏离
→ 纠偏
⑤ 收尾 · 验收
对照验收标准确认
→ 交付
Agent 最小闭环与验收底线
User Task → Plan → Tool Call → Observation → Revise Plan / Finish
  • 同一输入连续跑5次，关键步骤一致（可复现）
  • 工具失败时不会无限重试，有上限和兜底
  • 每一步都有日志，可追溯可回放
  • 人类可以在关键节点中断或接管
达不到这四条，就先别加更多工具。
练习卡 用 PMP 五阶段法做一个完整项目
动作
选一个1-4周可交付的小项目，按五阶段走完整流程
方法
每阶段产出对应文档（PROJ.md / PLAN.md / 交付物 / 纠偏记录 / 验收报告）
验收
五份产物齐全；Agent 闭环满足四条底线；最终交付对照验收标准通过
误区
跳过规划直接执行；监控只看进度不看偏离；收尾不对照启动时定的验收标准
时间
1-4 周（项目实际周期）
模块 04 / 长周期协同

带AI团队做大事

当项目跨越数天甚至数周，AI会丢失目标、偏离路线、遗忘决策。解决核心问题：怎么在长周期项目中保持AI不漂移。

三层协同架构
L1 · 执行层
VIBE 流水线
把想法做成产物。6步走完从灵感到实现的全过程。
idea → interaction → architecture → design → prototype → implement
L2 · 编排层
ORCHESTRATE
让长周期不迷失。里程碑、路线图、共驾仪表盘、验证门禁。
里程碑 + ROADMAP + dashboard共驾 + 验证门禁
L3 · 接力层
TASK-HANDOFF
跨班次连轴转。人下发任务，AI夜间执行，人验收。
人 → PROMPT.md → AI夜间执行 → DONE.md → 人验收
三大锚点
ANCHOR 01
目标锚定
把目标外置到持久文件 GOALS.md，不随对话漂移。每次启动会话先读目标，对齐再动手。
ANCHOR 02
证据验收
里程碑不是AI说了算，是证据说了算。双轨审计：AI自报 + 独立验证，对不上就回退。
ANCHOR 03
状态外置
项目状态存在于文件中，不存在于对话上下文中。上下文会丢，文件不会。
七步工作流
01
对话启动
02
主线程协调
03
里程碑审计
04
本地线程
05
状态同步
06
项目收尾
07
会话接力
模型分工
主线程
协调者（强模型）
负责理解目标、拆解任务、分配子代理、汇总结果。用最强模型，慢但准。
子代理
执行者（快速模型）
跑工具、写代码、出初稿。用快速模型，多并发，主线程把关。
审计员
独立审计（独立线程）
只做验证，不参与执行。对照证据和验收标准，红牌一票否决。
练习卡 模拟走一遍三层协同流程
动作
选一个需要2-3天跨会话的项目，搭L1+L2+L3最小骨架
方法
写GOALS.md + ROADMAP.md，用PROMPT.md/DONE.md跑一次夜间接力，主线程收尾审计
验收
跨3次会话目标不漂移；里程碑有证据；DONE.md对照PROMPT.md无遗漏
误区
只用对话不用文件；审计员和执行者同一个线程；里程碑只看AI自报不独立验证
时间
2-3 天
模块 05 / 判断力资产

从判断力到数字分身

成本最低、长期复利最大。每次做完一个重要判断后，用5问把隐性判断显式化。积累2-3个月，就有一份不可替代的职业判断资产。

判断档案 5 问法
Q1
你做了什么判断？（一句话描述决策本身）
Q2
为什么这么定？关键考量是什么？（列出2-3个决定因素）
Q3
当时排除了哪些选项？为什么排除？（被否的方案+否决理由）
Q4
如果重来一次，什么条件变了你会改判断？（可变条件）
Q5
下次遇到类似的，你的判断框架是什么？（可复用的 if-then 规则）
数字分身搭建路径
Step 1
积累判断档案
用5问法持续记录，攒够20条以上。这是原材料，没有这一步后面都是空架子。
Step 2
搭建结构化知识库
把判断样本按主题归类，提取共性规则，形成可检索的知识库。
Step 3
配置 Agent
技能 + 知识库 + 记忆 + 工具权限四件套，让Agent能调用你的判断框架。
Step 4
持续迭代
每次Agent判断有偏差，回写新档案。越用越像你，越用越准。
练习卡 积累 5 条判断样本
动作
回顾最近一周，挑5个你做过的重要判断，用5问法各写一份档案
方法
用上面的表单逐条填写，生成markdown后存档
验收
5条档案齐全；每条Q5都提炼出可复用的 if-then 规则；档案存进固定目录
误区
只写结论不写排除项；Q5写成空话没有条件触发；写完就丢不归档
时间
每条约10-15分钟，共约1小时
