## 5. 综合与五件硬清单

### 新接受的信念

**.codex/rules 是真实身份系统，.claude/rules 应被填充为桥接层。** 两套系统并行加载，.codex 是活的，.claude 是空的。空壳不等于"默认正确" — 它等于"浪费 context"。我之前假设 .claude 是主要系统只是因为它在文件系统层级更高，这不是有效证据。

### 新拒绝的旧信念

**"stalled = 需要关注"。** Molt 准备脚本的 stalled 标记是机械的（基于 mtime），不区分文档类型。reference-only 文档不需要周期性更新，blocked 文档需要解阻而非催更。一刀切标记 stalled 会制造虚假焦虑。

### 升级到 SOUL/USER/MEMORY 的模式

**"正式书面材料去技术过程描述"** — 从 Durable Lessons 升级为显式行为规则（在 MEMORY 中添加）。这不是偏好，是12天内被纠正3次的铁律。

### 该停止、降级或休眠的方向

**人机协同课程** — 阻塞在用户输入（JD课程03-10结构），42天无进展。不应继续标记为"进行中"，应降级为"等待解阻"。不删除，但不在 Current Context 中占显眼位置。

### 能力缺口

**缺少 topic 生命周期管理机制。** 当前 topic 只有"创建"和"更新"，没有"归档"、"reference-only 标记"、"blocked 状态"。导致每次 gardener/molt 都要重新判断 stalled topic 的真实状态。后续应在 topics/README.md 中增加状态标记约定。
