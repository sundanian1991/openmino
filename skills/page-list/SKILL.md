# 需求 → Page List

## Purpose

将用户提供的需求类文档快速转化为一份可直接交给原型生成 AI 使用的页面清单：

```text
需求文档 / PRD / 技术规格书
            ↓
      page-list.xlsx
```

## Inputs

支持以下输入：

- 用户直接粘贴的需求文本；
- 项目目录中的 `.md`、`.docx`、`.pdf`、`.txt` 文件；
- 已有需求文档、 PRD、技术规格书；
- 多份需求资料的组合输入。

无法确认的内容标注「待确认」，不擅自补充业务功能。

## Output

默认只生成：

```text
page-list.xlsx
```

读取 `assets/page-list-schema.json` 获取输出字段、字段定义和示例。不要依赖 Excel 模板文件。

优先使用当前环境的表格能力生成 `.xlsx`。如果当前环境无法生成 `.xlsx`，则按相同字段顺序输出 `page-list.csv`，不要因为缺少模板而停止。

## Page List 字段

Page List 至少包含以下字段：

1. 页面ID：使用 `P001`、`P002` 等连续编号；
2. 页面名称：使用稳定、清晰的页面名称；
3. 所属模块：页面所属的业务模块；
4. 二级菜单：有明确子业务域时填写，可空；
5. 三级菜单：只有确实需要时填写，可空；
6. 导航路径：串联菜单层级，可空；
7. 页面类型：列表页、表单页、详情页、仪表盘、看板页、个人页、登录页、消息页；
8. 端类型：桌面端或移动端；
9. 页面目标：用户进入页面后要完成的核心任务；
10. 页面布局：筛选+表格、卡片栅格、详情、表单、主从分屏、分步向导、时间线等；
11. 页面区块：只填写页面包含的区域名称和顺序，不重复填写具体字段和按钮；
12. 主要字段：页面展示的具体字段、指标或内容；
13. 主要按钮：用户可以执行的主要操作；
14. 关键交互：按钮点击后的跳转、弹窗、抽屉、返回或状态变化。

页面布局、页面区块、主要字段、主要按钮按以下边界填写：页面布局写整体排布类型；页面区块只写区域名称和顺序；主要字段写具体数据字段、指标或内容；主要按钮写具体操作。

## Page List 填写原则

### 1. 页面识别

从需求中识别：

- 功能模块；
- 用户需要完成的核心任务；
- 可独立进入的页面；
- 页面之间的跳转关系；
- 页面中的主要内容和操作。

一个功能只有在需要独立进入、完成独立任务或拥有独立内容结构时，才拆成独立页面。

### 2. 页面与弹窗的边界

- 独立路由、独立菜单入口或独立任务：拆成页面；
- 简单确认、删除、提示：记录为弹窗，不拆页面；
- 新增、编辑、查看：根据实际需求使用页面、弹窗或抽屉，不强制拆成四张页面；
- Tab、页面区块和局部展开：除非用户需要独立访问，否则不单独编号。

### 3. 模块与菜单

- 一级模块应来自需求中的业务模块，不凭空新增；
- 一个模块下有多个明确独立的子业务域时，使用二级菜单；
- 只有确实需要继续分组时才使用三级菜单；
- 不为了增加层级而强行拆菜单；
- 列表、看板等可从菜单直接进入的页面可进入导航树；
- 表单、详情、弹窗等通常通过页面操作进入，不作为独立菜单入口。

### 4. 页面内容

页面内容要具体，避免使用“基础信息”“相关内容”“数据展示”等空泛描述。页面区块不要混入字段和按钮。

推荐格式：

```text
页面布局：筛选+表格
页面区块：顶部、筛选区、统计区、列表区
主要字段：筛选区：设备类型、运行状态；统计区：设备总数、运行中数量、故障数量；列表区：设备名称、设备编号、设备类型、运行状态、责任人
主要按钮：筛选区：查询、重置；列表区：新增、查看、编辑、删除
```

### 5. 页面操作与交互

主要按钮只填写用户可见的操作，例如：新增、编辑、查看、删除、查询、重置、导出、提交、审核。

关键交互只写页面级结果：

```text
新增：打开新增设备抽屉
查看：跳转 P004 设备详情
删除：弹窗确认
提交：返回 P001 工单列表
```

不展开接口调用、数据库写入和后端实现细节。

### 6. CRUD 处理

对于明确存在数据维护需求的实体，可以按实际业务拆分列表、新增、编辑和详情页面，但不强制每个实体都生成完整 CRUD 页面。

例如：

- 台账管理：通常需要列表和详情，是否需要新增/编辑由需求决定；
- 监控数据：通常只需要看板、列表或详情；
- 系统日志：通常只需要查询、查看和导出；
- 移动端任务：通常以查看、处理和提交为主。

## Execution Steps

### Step 1 — 读取输入

读取并合并用户提供的需求资料，提取功能模块、用户任务、页面入口、页面内容和主要操作。

### Step 2 — 形成页面候选

按“独立入口 / 独立任务 / 独立内容结构”判断是否需要单独页面，区分页面、弹窗、抽屉和页面区块。

### Step 3 — 填写 Page List

读取 `assets/page-list-schema.json`，按其中的字段顺序填写页面清单。页面 ID 全局唯一，所有跳转引用的页面 ID 必须存在。

### Step 4 — 快速自检

交付前检查：

- 需求中的主要功能是否都有页面承载；
- 每个页面是否有明确页面目标；
- 页面区块和字段是否具体；
- 主要按钮是否都有对应的跳转、弹窗、抽屉或状态变化；
- 所有页面跳转 ID 是否存在；
- 是否出现没有需求依据的页面；
- PRD 或输入资料中的页面名称、模块和跳转是否与 Excel 一致。
