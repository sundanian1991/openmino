从零到上线：AI 做产品的5步路径
不需要会写代码，只需要会提需求、会验收、会判断。这是一个人用 AI 从零做出一个产品的真实流程——从想法到全球可访问。
预计时长 20 分钟 5 个阶段
学习目标
学完本节后：
• 说出用 AI 做产品的5个阶段和每个阶段的关键动作
• 理解"人负责判断，AI 负责执行"在真实项目中怎么落地
• 知道哪些坑必须提前防
前置知识：Step 05 的 Agent 模式 + Step 06 的三层协同框架
适用说明
这个案例来自一个真实项目——一个完全不懂代码的人用 AI 做出了一个产品，发布两个月后周活破30万。
虽然案例是做软件产品，但5步路径的方法适用于任何类型的 AI 协作项目——无论你是做运营、产品还是风控。
01
买装备（选 AI 编程工具）
先有工具，再谈方法
→
Coding Plan：选能买到的就行，差距没想象中大。Cursor、Copilot、Windsurf——三家都行，别纠结，先动手。

官方 Agent：买了哪家 Plan 就用哪家。Plan 自带的 Agent 就是你的第一个执行者，不需要额外配置。

核心原则：先有工具，再谈方法
产出：一个能写代码的 AI
产出：一个能操控文件的 Agent
02
打地基（名字→域名→服务器→备案）
这些必须前置，和开发并行
→
产品名字：先定！改名成本放大100倍。名字定下来，后面所有的域名、品牌、文案都围绕它展开。

域名：名字定下那一刻就注册，别等。好域名被抢走就没了，注册成本极低，没有理由拖。

服务器：产品得有永远在线的家。你本地跑得再好，关了电脑别人就看不到了。服务器是产品的永久居所。

备案：大陆域名必须备案，要和开发同步做。备案审批要时间（通常2-4周），等代码写完再备案，白白多等一个月。

核心原则：这些必须前置，和开发并行
产出：产品名
产出：域名
产出：服务器
产出：备案号
03
跑开发（Agent 干活 + 自己验收）
Agent 执行，你验收，不跳过验收
→
项目启动：建文件夹，让 Agent 驻扎进去。所有对话和操作都在这个项目目录里发生。

代码存 GitHub：私有仓库兜底。Agent 写的每一行代码都推到 GitHub，即使本地出问题也有备份。

怎么提需求：用 Plan 模式让它列计划，确认再执行。不要直接说"做一个xxx"，先让它拆解成可执行的步骤，你确认后再动手。

你做什么：确认 Plan 后放手，中途的确认节点就是验收窗口。你不是打字员，你是质检员。

怎么验收：在本地预览，你觉得对才是对。不要只看终端输出说"成功了"就信——打开浏览器，看到页面，点一遍，这才是验收。

AI 记不住怎么办：用项目文档兜底，防止新对话瞎编。把项目结构、技术选型、关键决策写进 README.md 或 docs/ 目录，每次新对话先喂给它。

核心原则：Agent 执行，你验收，不跳过验收
产出：一个本地可运行的产品
04
上线（部署→域名→全球可访问）
上线是起点，不是终点
→
部署：告诉 Agent 服务器 IP，说"部署到这台服务器"。Agent 会帮你配置运行环境、安装依赖、启动服务。

域名连接：让 Agent 把域名指向服务器、配好 HTTPS。用户输入你的域名，看到的应该是产品，不是报错。

验证：浏览器输入域名，看到产品——一个真实网址。这不是演示，是全球任何人都能访问的真实产品。

核心原则：上线是起点，不是终点
产出：一个全球可访问的产品
05
循环迭代（日常工作流）
安全迭代，改动都在分支，主分支永远稳定
→
七步循环：每一次改动都走这个流程，无论大小。
新建分支→ 说需求→ Agent 开发→ 检查→ 提交→ 合并→ 部署

分支保护：防止手抖推崩主分支。每次改动都在独立分支上做，确认没问题再合并回主分支。即使改坏了，主分支不受影响。

核心原则：安全迭代，改动都在分支，主分支永远稳定
产出：可持续迭代的工作流
铁律
两个铁律
5步路径的底层约束。违反任何一条，项目大概率翻车。
铁律一
不懂代码，但必须懂架构
你得知道产品的逻辑是怎么跑通的，不然 AI 糊弄你你都不知道。不需要能手写代码，但必须能看懂"这个页面从哪来数据、数据怎么处理、结果怎么展示"。架构感 = 你的验收能力。
铁律二
不让渡思考
AI 是执行者，你必须是那个知道"这件事应该怎么做"的人。你可以让 AI 写代码、画界面、配服务器，但"做什么"和"做对了没有"的判断永远在你手里。一旦你把思考也交给 AI，你就从合作者降级成了旁观者。
