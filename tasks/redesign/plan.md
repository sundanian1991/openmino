# 人机协同实战课 · 产品级改造方案

## 现状诊断（基于代码审计）

### 技术债
1. **11 个 HTML 文件各带 40-80 行重复 CSS** — `.course-header` `.chapter` `.sidebar-layout` 声明了 11 次
2. **无组件抽象** — 每个交互组件从头写 HTML+JS，无复用模式
3. **样式与内容耦合** — 关键样式 `max-width:1200px;margin:var(--space-5xl) auto 0;padding:0 var(--space-xl)` 内联在每个页面的第一个 div 上
4. **无品牌渗透** — Nothing Light tokens 只在 `theme.css` 定义，实际页面使用率偏低

### 体验债
1. **视觉扁平** — 所有页面白底+灰框+14px 字，无层次、无动效、无节奏
2. **交互浅** — 5/7 的交互组件是"填表单→出文本"，没有引导、验证、反馈
3. **内容轻薄** — 读/做比例约 8:2，大部分时间在看字
4. **无完成感** — 点完成按钮→回主页，没有总结、没有成就、没有延续感

---

## 改造架构

```
┌─────────────────────────────────────────────────┐
│                  设计系统层                        │
│  course.css (全局 tokens + 布局)                  │
│  theme.css (颜色/间距/字体 tokens)                 │
│  components/ (交互组件库)                          │
├─────────────────────────────────────────────────┤
│                  内容体验层                        │
│  渐进式引导 → 动手环节 → 即时反馈 → 产出沉淀       │
├─────────────────────────────────────────────────┤
│                  完成感闭环                        │
│  课末总结 → 下一课预告 → 成就系统 → 进度可视化      │
└─────────────────────────────────────────────────┘
```

## Phase 0: 设计系统统一（基础）

**目标**：消除所有重复 CSS，建立可维护的组件体系

### Task 0.1 — 抽取全局样式
- 将 11 个页面共用的 `.course-header` `.chapter` `.sidebar-layout` `.course-desc` `.course-meta` `.finish-area` `.sidebar-*` 合并到 `assets/course.css`
- 每页只保留交互组件专有样式（如 `.launcher-grid` `.j-scene-tabs`）

**影响文件**：`step-01.html` ~ `step-11.html`（全部清理）
**验证**：每页删除无报错，视觉无回归

### Task 0.2 — 构建组件 CSS 片段库
- 将反复出现的模式提取为可复用的 CSS 片段：
  - `.interactive-demo`（所有页面的交互容器）
  - `.demo-header` / `.demo-icon` / `.demo-title` / `.demo-sub`
  - `.callout` / `.callout.info` / `.callout.gold`
  - `.btn` / `.btn-primary`
  - `.tpl-textarea` / `.launcher-textarea` / `.j-textarea` → 统一为 `.field-input`
  - `.tpl-preview` / `.launcher-preview` / `.j-preview` → 统一为 `.field-preview`

**验证**：6 个页面引用 `field-input` 组件后样式一致

### Task 0.3 — 建立样式命名约定
- 组件类：`cmp-{name}`（如 `cmp-tabs`、`cmp-builder`）
- 状态类：`is-{state}`（如 `is-active`、`is-done`、`is-error`）
- 布局类：`layout-{name}`（如 `layout-sidebar`）
- 统一规格，现有内联 style 能抽则抽

**产出**：`assets/CODING-STANDARD.md`

## Phase 1: 视觉层次重建（质感）

**目标**：从"白纸"变成"有层次、有节奏、有品牌感的产品"

### Task 1.1 — 排版体系
- 当前：所有正文 14px，标题 16px/22px，层级拉不开
- 改造：
  - 页面标题 `28px` / `700`（现 22px）
  - 章节标题 `18px` / `600`（现 16px）
  - 正文 `14px` / `400`（不变，但行距从 1.7 调到 1.8）
  - 辅助文字 `12px` → `11px`
  - 代码/标签 `10px` → `9px`（更紧凑）
- 配套行距、段距、标题下间距系统化

### Task 1.2 — 品牌色渗透
- 当前：主色 `#D71921`(accent) 只出现在 `index.html` 的导航和图标
- 改造：
  - 章节编号 `.chapter-num` 左侧统一加 accent 色块（3px 竖条）
  - 完成按钮使用 accent 色渐变边框
  - 交互组件边框从 `var(--border)` 升级为带微色相的 `rgba(215,25,33,0.12)`
  - 进度条渐变从纯色改为 `accent → purple` 渐变

### Task 1.3 — 间距节奏
- 当前：所有间距靠 `var(--space-md)` (16px) 硬算，每个页面段落间距一致
- 改造：
  - 章节间距从 `margin-bottom: var(--space-md)` → `var(--space-xl)` (32px)
  - 段落间距从 `<br>` → 统一 `margin-bottom: 1em`
  - 交互组件内部区块增加 `padding: var(--space-xl)` 而非 `var(--space-md)`
  - 页头和页脚增加额外呼吸空间

### Task 1.4 — 动效系统（轻量）
- 当前：只有 CSS transition 0.15s
- 改造：
  - 页面入场：`.chapter` 按顺序 `fadeInUp`（translateY(12px)→0, opacity 0→1, 间隔 80ms）
  - 交互反馈：
    - 保存成功：按钮闪烁绿光 0.3s + 图标跳动
    - 复制成功：toast 通知（右下角出现，2s 后消失）
    - 完成课程：页面级庆祝动画（confetti 或 checkmark 放大）
  - Tab/场景切换：内容 `fadeIn` 0.2s
- **约束**：只用 CSS animation + JS class 切换，不引入第三方动画库

### Task 1.5 — 统一交互容器
- 当前：6 种不同名的交互组件（`triage-grid`、`template-show`、`j-builder`、`launcher-grid`、`check-grid`、`evo-steps`）
- 改造：统一交互容器模式
  ```
  .cmp-card — 圆角+阴影+悬停抬升
  .cmp-field — 统一输入区样式（label + input/textarea）
  .cmp-output — 统一输出区样式（preview + buttons）
  .cmp-divider — 统一分割线
  ```

## Phase 2: 交互深度升级（内容体验）

**目标**：从"填表→出文本"变成"渐进引导→即时反馈→产出沉淀"

### Task 2.1 — 渐进式引导模式
- 为 5 个表单类交互组件（Step 04/05/07/08/09）增加步骤指示器
- 模式：Step 1/3 → Step 2/3 → Step 3/3 递进，每步填完才解锁下一步
- 配套：步骤编号圆点 + 连接线 + 完成打勾

### Task 2.2 — 即时验证与反馈
- Step 04 判断标准：填完后给"完整性检查"——缺什么提示补什么
- Step 05 Agent 指令：生成后自动检查是否包含"目标""边界""验收"三要素
- Step 08 项目启动器：检查里程碑是否 > 2 个、风险是否填了

### Task 2.3 — 内容密度反转（读:做 = 3:7）
- 每节课当前读约 500-800 字，改为 300 字以内
- 压缩方式：
  - 概念部分用一句话 + 展开"点击了解更多"（而非全文展示）
  - 案例部分用交互式点选（而非文字描述）
  - 新增"快速实践"环节——直接给模板让用户填空

### Task 2.4 — 产出沉淀视觉化
- 当前：保存后只在页面底部显示一条文字
- 改造：右侧增加"我的产出"侧边栏，显示本课所有已保存的产出
- 每节课结束时显示"你在这节课收获了：X 条判断标准 / Y 个模板 / Z 条指令"

## Phase 3: 完成感闭环（体验完整）

**目标**：每节课有完整的故事弧——开始→动手→总结→延续

### Task 3.1 — 课末总结卡片
- 每节课完成后显示总结卡片：
  - 你学到了什么（3 个要点）
  - 你产出了什么（保存的条目列表）
  - 下一步推荐（基于当前进度 + 岗位）
- 不要跳转到 `index.html` 就完事，要在当前页面显示总结

### Task 3.2 — 成就系统
- 基于现有 localStorage 数据扩展
- 成就类型：
  - 🏅 完成者（完成所有 11 步）
  - 📐 判断大师（保存 ≥3 条判断标准）
  - 🚀 项目启动（在 Step 08 保存了项目）
  - 🧠 数字分身（在 Step 10 三项检查全勾）
  - ⚡ 全对通关（练习测验全对）
- 成就展示：index.html 底部新增"成就墙"

### Task 3.3 — 进度可视化
- 当前：环形进度只显示百分比数字
- 改造：环形进度增加分段颜色（核心路径一段色、进阶一段色）
- 每完成一课，过渡动画填充

### Task 3.4 — 导出/分享
- 底部增加"导出我的产出"按钮 → 下载 markdown 合集
- 增加"打印模板"功能（一键打开所有模板的打印视图）


## 拒绝清单（明确不做）

1. ❌ 不引入前端框架（React/Vue/Svelte）——保持纯 HTML/CSS/JS
2. ❌ 不增加后端——纯静态页面 + localStorage
3. ❌ 不做响应式移动端优先——桌面端优先，900px 断点保底
4. ❌ 不替换现有 `theme.css`——在其之上扩展而非重构
5. ❌ 不做 i18n——中文唯一
